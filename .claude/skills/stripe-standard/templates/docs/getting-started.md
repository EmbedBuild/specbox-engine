# Stripe Standard — Getting started (5-minute setup)

> Auto-generated by `/stripe-standard` for **{project_name}**.

You just ran `/stripe-standard`. Here's what to do next to get a paid signup
working end-to-end in **5 minutes**.

## 0. Prerequisites you should already have

- A **Stripe account** in test mode (free, no Tax/Connect needed).
- The **Stripe CLI** locally: <https://stripe.com/docs/stripe-cli>.
- **Supabase CLI** initialized: `supabase init` ran, `supabase/config.toml` exists.
- Your `.env` has at least:
  ```
  STRIPE_SECRET_KEY=sk_test_...
  STRIPE_PUBLISHABLE_KEY=pk_test_...
  ```

## 1. Apply the SQL migrations

```bash
supabase db push
```

You should see 4 new tables: `stripe_customers`, `stripe_subscriptions`,
`stripe_processed_events`, plus RLS policies.

## 2. Deploy the Edge Functions

```bash
supabase functions deploy stripe-create-customer
supabase functions deploy stripe-create-subscription
supabase functions deploy stripe-create-payment-intent
supabase functions deploy stripe-create-checkout-session
supabase functions deploy stripe-create-portal-session
supabase functions deploy stripe-webhook
# Only if metered mode active:
supabase functions deploy stripe-report-usage
```

> The skill sets up the function names; you may not have all 7 if you only
> activated some modes. Skip the ones that don't exist.

## 3. Get the webhook secret from Stripe CLI

In a separate terminal, run:

```bash
stripe listen --forward-to https://<your-project-ref>.supabase.co/functions/v1/stripe-webhook
```

Copy the `whsec_*` it prints. That's `STRIPE_WEBHOOK_SECRET`.

## 4. Inject the 3 secrets into Supabase

Three options, in order of preference:

### Option A — `specbox-supabase-mcp` (automatic)

If you have the MCP registered:

```
mcp__specbox-supabase__set_edge_secret_tool({
  supabase_pat: "sbp_...",
  project_ref: "<your-ref>",
  secrets: {
    STRIPE_SECRET_KEY:       "sk_test_...",
    STRIPE_WEBHOOK_SECRET:   "whsec_...",
    STRIPE_PUBLISHABLE_KEY:  "pk_test_..."
  },
  confirm: true,
  reason: "/stripe-standard initial setup"
})
```

### Option B — Supabase CLI

```bash
supabase secrets set STRIPE_SECRET_KEY=sk_test_...
supabase secrets set STRIPE_WEBHOOK_SECRET=whsec_...
supabase secrets set STRIPE_PUBLISHABLE_KEY=pk_test_...
```

### Option C — Dashboard

<https://supabase.com/dashboard/project/{project_ref}/settings/functions>

## 5. (Optional) Create products + prices

If you have `specbox-stripe-mcp` v0.2 registered, the skill can create your
catalog automatically:

```
mcp__specbox-stripe__setup_products_and_prices_tool({
  stripe_api_key: "sk_test_...",
  catalog: [
    {
      "tier_key": "basic",
      "product_name": "Basic plan",
      "unit_amount": 500,
      "currency": "eur"
    },
    {
      "tier_key": "pro",
      "product_name": "Pro plan",
      "unit_amount": 2000,
      "currency": "eur"
    }
  ],
  project_hint: "{project_name}"
})
```

The result writes `tier_mapping` to `doc/tracking/stripe-standard-tier-mapping.json`
so your UI can read price IDs from there.

If you skip this, do it manually in the Stripe dashboard: <https://dashboard.stripe.com/test/products>.

## 6. Smoke-test in dev

```bash
npm run dev   # or flutter run
```

1. Sign up a new user.
2. Navigate to /pricing (component generated in UC-006 / UC-009).
3. Click on a tier.
4. PaymentElement (web) or PaymentSheet (mobile) should appear.
5. Use card **4242 4242 4242 4242**, any future date, any CVC, any postal code.
6. Confirm. You should land on `/billing/return` (web) or get a success
   PaymentSheet result (mobile).
7. Open the dashboard at <https://dashboard.stripe.com/test/customers> and
   you should see the new customer + subscription.

## 7. Verify the webhook works

Look at the `stripe listen` terminal — it should print the events flowing in.

Check the DB:

```sql
SELECT * FROM stripe_subscriptions ORDER BY updated_at DESC LIMIT 5;
SELECT * FROM stripe_processed_events ORDER BY processed_at DESC LIMIT 10;
```

If `stripe_subscriptions` has a row with `status='active'` for your test user,
**you're done**.

## 8. Going to production (later)

1. Activate Stripe Tax if you sell in EU and want to collect VAT.
2. Configure the Customer Portal at
   <https://dashboard.stripe.com/test/settings/billing/portal>.
3. Switch from `sk_test_*` to `sk_live_*` in your secrets.
4. Set up a real webhook endpoint at
   <https://dashboard.stripe.com/test/webhooks> (Stripe CLI is dev only).
5. Run `get_setup_status(account_mode='standard')` from `specbox-stripe-mcp`
   to validate everything is `verdict='ready'` before going live.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `invalid_signature` from webhook | wrong `STRIPE_WEBHOOK_SECRET` | re-copy from `stripe listen` and re-set |
| 401 Unauthorized from Edge Functions | JWT not sent or expired | check `supabase.auth.getSession()` |
| `customer_not_found` from create-subscription | user signed up before deploying | call stripe-create-customer for the user manually |
| PaymentSheet doesn't appear (Flutter) | `Stripe.publishableKey` missing | check `--dart-define=STRIPE_PUBLISHABLE_KEY=...` |
| Apple Pay not showing | merchant identifier missing | set `STRIPE_APPLE_MERCHANT_ID` and configure on Apple Developer portal |
| stripe-safety-guard blocks your edit | you have an anti-pattern | read the error message — it tells you which one and where |

## Useful runbooks

- **Refund a charge**: use the official Stripe MCP — `stripe.refunds.create({payment_intent: 'pi_...'})`.
- **Cancel a subscription immediately** (vs at period end): call
  `stripe.subscriptions.cancel(sub_id)` from the Stripe MCP.
- **Test 3DS challenges**: card `4000 0000 0000 3220` triggers required SCA.
- **Test renewal failure**: card `4000 0000 0000 0341` (declines on renewal).
