# [UC-D002] Ejecutar /discovery en modo bootstrap (primer uso en proyecto)

- **Estado**: Todo
- **US padre**: US-D01
- **Horas estimadas**: 8
- **Actor**: Engine
- **Milestone**: H2
- **PRD**: [doc/prd/discovery_module_v6_prd.md](../../../doc/prd/discovery_module_v6_prd.md)

## Descripción

Cuando doc/app/app_market.md está vacío o ausente, /discovery [feature_name] detecta la situación y entra en modo bootstrap: primero completa el nivel producto (ICPs canónicos, JTBDs globales, NSM, posicionamiento), luego desciende al nivel feature.

## Acceptance Criteria

| AC | Descripción | Estado |
|----|-------------|--------|
| AC-01 | [AC-01] La detección de app_market.md vacío/ausente lanza modo bootstrap automáticamente sin requerir flag explícito. [JR-3.1, JE-3.2] | Pending |
| AC-02 | [AC-02] El modo bootstrap muestra mensaje pedagógico inicial: 'Antes de definir esta feature, necesitamos definir para quién es el producto entero. Esto solo se hace una vez por proyecto.' [JE-3.2, JE-3.3] | Pending |
| AC-03 | [AC-03] La fase producto completa los 5 bloques esenciales de app_market.md: ICPs primarios, no-ICPs, JTBDs racionales globales, JTBDs emocionales globales, NSM. Los bloques opcionales (posicionamiento, anti-features) se ofrecen pero pueden saltarse. [JR-2.2, JR-3.1] | Pending |
| AC-04 | [AC-04] El app_market.md generado incluye sección 'Exportable copy' con extractos pre-formateados para landing, LinkedIn post y elevator pitch, derivados automáticamente de ICPs+JTBDs. [JR-2.2] | Pending |
| AC-05 | [AC-05] Tras completar app_market.md, el flujo desciende automáticamente al modo estándar de UC-D001 para la feature solicitada. [JR-1.1] | Pending |
