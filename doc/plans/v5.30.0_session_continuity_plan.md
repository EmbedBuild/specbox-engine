> **Codename**: "Session Continuity"
> **Predecessor**: v5.29.0 "Cognitive Load Reduction"
> **Estado**: PLAN AUTOPILOT — listo para `/implement`
> **Estimación**: ~14h (3 días intensos)
> **Riesgo**: BAJO (capa aditiva, no toca pipeline existente)

---

## 1. Contexto y problema

A medida que el usuario trabaja más en autopilot con SpecBox, las sesiones de Claude Code se hacen largas. Cuando el harness se acerca al límite de la ventana de contexto, **propone proactivamente compactar o iniciar nueva sesión**. Esto rompe el flujo y genera tres riesgos:

1. **Pérdida de estado fino**: el checkpoint `.quality/evidence/{feature}/checkpoint.json` solo guarda `{phase, branch, status}` — pierde decisiones tomadas mid-session, hot files, próximo paso concreto.
2. **Repreguntas en sesión nueva**: la nueva sesión no encuentra un punto de entrada con el resumen del estado, así que vuelve a leer archivos hasta deducirlo.
3. **Sin instrucción al harness**: Claude no sabe que SpecBox tiene persistencia más rica que el resumen nativo, por lo que la conversación sobre "compactar o no" se repite cada vez.

Diagnóstico completo (con file:line refs) en la conversación que generó este plan. Resumen ejecutivo de los gaps identificados:

| # | Gap | Síntoma observable |
|---|-----|--------------------|
| G1 | No hay `/handoff` ni `.quality/handoff.md` | La nueva sesión arranca ciega |
| G2 | Engram session-summary es prosa libre, no JSON | `mem_search` no puede filtrar por UC/branch |
| G3 | `context-budget.sh` existe pero ninguna skill lo invoca antes de leer | Reads masivos sin warning |
| G4 | Documentos canónicos solo se cargan en Paso 0.0 de skills específicas | Tareas ad-hoc no heredan stack/convenciones |
| G5 | Sin SessionStart hook propio | La sesión no inyecta contexto crítico al arranque |
| G6 | CLAUDE.md no instruye al harness sobre el protocolo de compactación | Claude propone compactar "a ojo" |

---

## 2. Objetivos de v5.30.0

**Largo plazo**: trabajar con precisión sobre carga de contexto en tareas largas, con fuentes de verdad bien estructuradas y handoffs deterministas entre sesiones.

**Tangibles para esta release**:

- O1. Una sesión que cierra (por compactación, `/clear`, o cierre voluntario) deja un `handoff.md` legible por humano y máquina.
- O2. Una sesión nueva, en su primer turno, dispone del estado fino del proyecto sin necesidad de exploración.
- O3. El usuario puede llamar `/handoff` explícitamente en cualquier momento para forzar la persistencia.
- O4. Claude tiene en CLAUDE.md un protocolo claro: *antes de proponer compactar → ejecutar `/handoff`*.
- O5. El consumo de contexto es **observable en vivo** (no solo al cerrar), via heartbeat enriquecido y métrica en Sala de Máquinas.
- O6. Reads de archivos pesados emiten warning preventivo cuando comprometen >5% de la ventana.

**Fuera de alcance** (reservado para v5.31+):
- Refactor de `/implement` para delegar fases a Tasks aisladas (idea 6 del análisis original) — es una release dedicada.
- UI dashboard de "context pressure" — esta release deja la métrica disponible vía MCP, la UI viene después.

### 3.2 Skill `/handoff`

Nueva skill `direct` (escribe filesystem). Frontmatter:

```yaml
---
name: handoff
description: >
  Persiste el estado fino de la sesión actual a .quality/handoff.md y a Engram
  como observación estructurada. Use when the user says "handoff", "save state",
  "guarda contexto", "voy a hacer compactación", or before /clear.
context: direct
---
```

**Flujo** (`.claude/skills/handoff/SKILL.md`):

1. Lee estado actual: `git diff --stat`, `git log -10`, `.quality/active_uc.json`, último checkpoint, `.quality/evidence/*/healing.jsonl`, feedback abierto.
2. Pide a la conversación actual (vía instrucción al modelo): "Lista las decisiones tomadas, preguntas pendientes y próximo paso concreto en formato del template."
3. Renderiza Markdown final + escribe `.quality/handoff.md`.
4. Llama `mem_save` (Engram) con `topic="handoff"` + payload JSON estructurado: `{project, branch, active_uc, decisions, hot_files, next_step, observation_ids: [...]}`.
5. Llama heartbeat con `last_operation="handoff"` para marcar el evento en Sala de Máquinas.
6. Devuelve al usuario:
   ```
   Handoff persistido (.quality/handoff.md, Engram obs-XXX).
   Podés cerrar sesión, compactar o ejecutar /clear con seguridad.
   ```

**Triggers automáticos** (sin pedirlo el usuario):
- Cuando el modelo detecta que va a sugerir compactación → debe llamar `/handoff` ANTES.
- Esto se enforce vía instrucción en CLAUDE.md sección nueva (ver §3.6).

### 3.3 Hook `session-start.mjs`

Nuevo hook tipo `SessionStart` registrado en `.claude/settings.json`. Inyecta contexto al primer turno via stdout (Claude Code lo lee como `additionalContext`).

**Lógica**:

```
1. Si existe .quality/handoff.md y mtime < 24h:
     → emit el contenido completo como contexto (clamp a ~2k tokens)
2. Si existe .quality/active_uc.json:
     → emit "UC activo: {uc_id} — checkpoint Phase {N} en {branch}"
3. Si existe doc/app/app_spec.md:
     → emit zona "tracking_backend" + "autopilot" (siempre relevantes)
4. Si lo anterior está stale (>24h):
     → emit warning "Estado del proyecto puede estar obsoleto, considerá refresh"
```

Output máximo: 3.5k tokens. Mejor menos contexto preciso que mucho contexto vago.

### 3.4 Engram session-summary estructurado

Refactor de `on-session-end.mjs` líneas 81-89:

**Antes**:
```js
const engramSummary = `Session ended at ${ts} | Files modified: ${n} | ...`;
spawn('engram', ['save', 'session-summary', engramSummary], {...});
```

**Después**:
```js
const payload = {
  type: 'session_end',
  schema_version: 1,
  project: basename(cwd),
  ended_at: timestamp,
  files_modified: filesModified,
  context_tokens_est: contextTokens,
  healing_events: healingEvents,
  active_feature: activeFeature,
  branch: git('branch --show-current'),
  handoff_path: fileExists('.quality/handoff.md') ? '.quality/handoff.md' : null,
};
spawn('engram', ['save', `session:${payload.project}:${payload.branch}`,
  JSON.stringify(payload)], {...});
```

Esto permite a la próxima sesión hacer `mem_search "session:specbox-engine:feature/uc-021"` y traerse el snapshot exacto.

### 3.5 Hook `pre-read-budget-guard.mjs`

PreToolUse(Read) no-bloqueante. Estima tamaño del archivo a leer (en chars) usando `stat`, lo divide por 4, y si supera 5% de 1M (50k tokens) emite warning:

```
[BUDGET] Read de archivo grande detectado: lib/foo.dart (~62k tokens, 6.2% de la ventana).
         Considerá usar Grep o Explore en vez de Read completo.
```

No bloquea — solo informa. El agente decide.

Configurable via `.claude/settings.local.json` → `specbox.context_budget.warn_pct` (default 5).

### 3.6 Sección nueva en CLAUDE.md

Bloque dedicado, ~30 líneas, después de "Context Engineering":

```markdown
## Session Continuity (v5.30.0)

SpecBox provee persistencia más rica que la compactación nativa. Antes de proponer
"compactar" o "iniciar nueva sesión":

1. **Ejecutá `/handoff`** — persiste estado fino a `.quality/handoff.md` y Engram.
2. Confirmá al usuario que el handoff fue exitoso.
3. Solo entonces, sugerí compactar/cerrar.

La nueva sesión arranca con el handoff cargado vía SessionStart hook. No hace falta
que el usuario "te ponga al día" — la primera lectura ya tiene el estado.

**Cuándo es obligatorio el handoff**:
- Antes de proponer compactación al usuario.
- Antes de `/clear`.
- Cuando hay UC activo (`.quality/active_uc.json` existe).
- Cuando hay checkpoint < 30 min.

**Cuándo es opcional**:
- Cierre voluntario sin trabajo en progreso.
- Sesiones puramente exploratorias.
```

## 6. Riesgos y mitigaciones

| Riesgo | Probabilidad | Impacto | Mitigación |
|--------|-------------|---------|------------|
| SessionStart hook inyecta demasiado contexto y degrada inicio | Media | Alto | Hard cap 3.5k tokens, telemetría del tamaño |
| Engram structured rompe búsquedas existentes | Baja | Medio | Mantener backwards-compat: nuevo topic key, no toca el viejo |
| `/handoff` se vuelve molesto si Claude lo dispara siempre | Media | Bajo | CLAUDE.md instruye disparo solo cuando *iba a sugerir compactar*, no en cada turno |
| pre-read-budget-guard genera ruido en proyectos con muchos archivos grandes | Media | Bajo | Threshold configurable, default conservador (5%) |
| Conflicto con compactación nativa de Claude Code | Baja | Medio | El handoff es additivo: si el harness compacta igual, el archivo persiste y la nueva sesión lo lee |
