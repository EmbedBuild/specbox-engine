# UC-628: Correlacionar logs structlog con spans OTel (trace_id + span_id en cada log line)

- **Estado**: Backlog
- **US padre**: US-MCP-OBSERVABILITY
- **Horas estimadas**: 2.0
- **Actor**: Engine

## Acceptance Criteria

| AC | Descripción | Estado |
|----|-------------|--------|
| AC-01 | [AC-01] `server/observability/logging.py` exporta `add_otel_context_processor(logger, method_name, event_dict)` que retorna `event_dict` enriquecido con keys `trace_id` (32 hex chars) y `span_id` (16 hex chars) cuando hay span activo; un test dentro de `tracer.start_as_current_span` verifica que las keys se anaden. | PENDING |
| AC-02 | [AC-02] El processor es no-op (retorna `event_dict` inalterado) cuando no hay span activo o cuando OTel no esta inicializado; 2 tests cubren ambos casos. | PENDING |
| AC-03 | [AC-03] `server/server.py` anade el processor al stack de structlog SOLO dentro del bloque condicional `if SPECBOX_OBSERVABILITY_ENABLED == 'true'`; el test importa server con env OFF y verifica que `add_otel_context_processor` no esta en la lista de processors configurados. | PENDING |
| AC-04 | [AC-04] Un test end-to-end: dentro de un span activo, un `logger.info('msg', foo='bar')` produce output JSON que contiene `trace_id`, `span_id`, `foo='bar'`, `event='msg'` simultaneamente (verifica que la correlacion esta intacta). | PENDING |
